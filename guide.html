Weather Dashboard: розбір коду

Пошук міста, поточна погода і прогноз на 3 дні. Сервер на Node.js без залежностей ділиться на три шари: Controller, Service, Client. Нижче видно, що робить кожен файл і чому код розкладено саме так.

Node.js ≥ 20.12 0 залежностей OpenWeatherMap 2.5 node:test

1. Загальна картина

Браузер ніколи не звертається до OpenWeatherMap напряму. Він питає наш сервер, а сервер додає API-ключ і сам ходить до зовнішнього API. Так ключ лишається на сервері.

Залежності йдуть тільки вправо. Controller викликає Service, Service викликає Client. Жоден шар не знає про те, що лівіше від нього.

ШарВідповідає заНе знає про
Controllerпрочитати ?city=, віддати JSON і статусбізнес-правила
Serviceвалідація, мапінг у свою структуру, прогноз на 3 дніHTTP, URL, ключ
Clientзапити до OpenWeatherMap, коди 401/404/429що робити з даними

Порядок: server.js → Controller → Service → Client → тест. Так видно, як із запиту складається відповідь.

3. Шлях одного запиту

Користувач вводить Kyiv і натискає «Шукати».

  1. app.js робить fetch('/api/weather?city=Kyiv'). Назва проходить через encodeURIComponent, тож пробіли й кирилиця не ламають URL.
  2. server.js бачить шлях /api/weather і передає запит у getWeather (Controller). Інші шляхи йдуть у serveStatic.
  3. Controller бере city з url.searchParams і викликає weatherService.getWeather(city).
  4. Service обрізає пробіли, перевіряє довжину (1–100 символів), потім через Promise.all запускає два запити одночасно: поточна погода і прогноз.
  5. Client формує URL з appid, units=metric, lang=ua, робить fetch, а за статусом відповіді кидає AppError або повертає JSON.
  6. Service перетворює два сирі JSON в одну свою структуру (DTO) і викликає buildDailyForecast.
  7. Controller віддає DTO зі статусом 200. Якщо хтось кинув AppError, він віддає { error } з тим статусом, який у помилки.
  8. app.js малює картку «зараз» і три картки прогнозу.

4. server.js: збирання застосунку

server.jscomposition root
// Composition root: єдине місце, де «збираємо» застосунок і звʼязуємо шари між собою.
//   HTTP → controller → service → client → OpenWeatherMap
import http from 'node:http';
import { loadConfig } from './src/config.js';
import { createOpenWeatherClient } from './src/clients/openWeatherClient.js';

  config = loadConfig();
} catch (err) {
  console.error(err.message);
  process.exit(1);
}

// Dependency Injection вручну: кожен шар отримує те, що йому потрібно, через аргументи.

const weatherService = createWeatherService({ client });
const getWeather = createWeatherController({ weatherService });
const serveStatic = createStaticHandler(config.publicDir);

http

    const url = new URL(req.url, `http://${req.headers.host}`);
    if (req.method !== 'GET') return void res.writeHead(405).end();
    if (url.pathname === '/api/weather') return void getWeather(req, res, url);
    serveStatic(req, res, url);
  })
  .listen(config.port, () => console.log(`Weather Dashboard: http://localhost:${config.port}`));

Це єдине місце, де шари створюються і з'єднуються. Решта файлів експортують фабрики (createX) і нічого не створюють самі.

Dependency Injection вручну

Фабрика createWeatherService({ client }) бере клієнта аргументом. Сервіс не пише import { client } ... і не залежить від конкретної реалізації. У тесті сюди передають фейк, у продакшені справжній Client. Для цього не потрібен жоден фреймворк.

Також тут перевіряється конфіг: якщо ключа немає, програма завершується з зрозумілим повідомленням, а не падає пізніше з 401.

5. Controller: HTTP-шар

src/controllers/weatherController.jsшар 1
// ШАР 1 — Controller (HTTP-шар). Читає запит, викликає сервіс, формує відповідь.
// Жодної бізнес-логіки: лише «HTTP in → service → HTTP out».
import { AppError } from '../errors.js';

function sendJson(res, status, body) {
  res.writeHead(status, { 'Content-Type': 'application/json; charset=utf-8' });
  res.end(JSON.stringify(body));
}

export function createWeatherController({ weatherService }) {
  return async function getWeather(req, res, url) {
    try {
      const data = await weatherService.getWeather(url.searchParams.get('city'));
      sendJson(res, 200, data);
    } catch (err) {
      if (err instanceof AppError) return sendJson(res, err.status, { error: err.message });
      console.error(err); // непередбачена помилка — деталі лише в лог, клієнту загальне повідомлення
      sendJson(res, 500, { error: 'Внутрішня помилка сервера.' });
    }
  };
}
  • Контролер не містить логіки: бере параметр, викликає сервіс, віддає результат.
  • err instanceof AppError означає «очікувана помилка»: статус і текст уже вирішені нижче, контролер їх лише віддає.
  • Будь-яка інша помилка (баг) іде в консоль, а клієнт отримує загальне 500. Деталі помилки назовні не виходять.
Підводний камінь

Кожна функція, що кидає, має бути всередині try. Інакше відхилений Promise у http.createServer залишить запит без відповіді.

6. Service: логіка і власний формат даних

src/services/weatherService.jsшар 2
// ШАР 2 — Service (бізнес-логіка). Нічого не знає ні про HTTP, ні про URL OpenWeatherMap.
// Залежності (client, now) приходять ззовні → у тестах підставляємо фейки (Dependency Injection).
import { AppError } from '../errors.js';

const DAYS = 3;

// dt — UNIX-секунди (UTC), timezone — зсув міста від UTC у секундах → "YYYY-MM-DD" за місцевим часом.
const localDate = (dt, tz) => new Date((dt + tz) * 1000).toISOString().slice(0, 10);
const localHour = (dt, tz) => new Date((dt + tz) * 1000).getUTCHours();

// Чиста функція (без побічних ефектів) — легко тестувати.
// Прогноз = 40 записів по 3 год. Групуємо по днях міста й беремо 3 дні після сьогоднішнього.
export function buildDailyForecast(forecast, nowMs) {
  const tz = forecast.city.timezone;
  const today = localDate(Math.floor(nowMs / 1000), tz);

  const byDay = new Map();
  for (const item of forecast.list) {
    const day = localDate(item.dt, tz);
    if (day === today) continue;
    if (!byDay.has(day)) byDay.set(day, []);
    byDay.get(day).push(item);
  }

  return [...byDay.entries()].slice(0, DAYS).map(([date, items]) => {
    const temps = items.map((i) => i.main.temp);
    const humidity = items.reduce((sum, i) => sum + i.main.humidity, 0) / items.length;
    // Іконка/опис — із запису, найближчого до полудня
    const noon = items.reduce((best, i) =>
      Math.abs(localHour(i.dt, tz) - 12) < Math.abs(localHour(best.dt, tz) - 12) ? i : best,
    );
    return {
      date,
      min: Math.min(...temps),
      max: Math.max(...temps),
      humidity: Math.round(humidity),
      icon: noon.weather[0].icon.replace('n', 'd'),
      description: noon.weather[0].description,
    };
  });
}

export function createWeatherService({ client, now = Date.now }) {
  return {
    async getWeather(rawCity) {
      const city = String(rawCity ?? '').trim();
      if (!city || city.length > 100) throw new AppError(400, 'Вкажи назву міста (до 100 символів).');

      const [current, forecast] = await Promise.all([client.getCurrent(city), client.getForecast(city)]);

      // Мапимо чужий формат у НАШ (DTO). Фронтенд залежить лише від цієї форми.
      return {
        city: current.name,
        country: current.sys.country,
        description: current.weather[0].description,
        icon: current.weather[0].icon,
        temp: current.main.temp,
        feelsLike: current.main.feels_like,
        humidity: current.main.humidity,
        pressure: current.main.pressure,
        windSpeed: current.wind.speed,
        forecast: buildDailyForecast(forecast, now()),
      };
    },
  };
}

Що тут важливо

  • Валідація стоїть до будь-якого запиту: порожнє місто не витрачає ліміт API.
  • DTO. Фронтенд читає temp, feelsLike, windSpeed, а не main.temp чи wind.speed. Якщо OpenWeatherMap змінить формат, правка буде тільки тут.
  • now = Date.now як параметр. «Сьогодні» залежить від годинника. Параметр дає змогу зафіксувати час у тесті.
  • buildDailyForecast експортується окремо. Це чиста функція: ті самі вхідні дані дають той самий результат, без мережі й побічних ефектів. Її найпростіше тестувати.

7. Client: адаптер до OpenWeatherMap

src/clients/openWeatherClient.jsшар 3
// ШАР 3 — Client (патерн Adapter / Gateway).
// Єдине місце, яке знає, ЯК говорити з OpenWeatherMap: URL, параметри, коди відповідей.
// Повертає «сирий» JSON як є; помилки HTTP перетворює на AppError.
import { AppError } from '../errors.js';

const BASE_URL = 'https://api.openweathermap.org/data/2.5';

export function createOpenWeatherClient({ apiKey, fetchFn = fetch }) {
  async function request(endpoint, city) {
    const url = new URL(`${BASE_URL}/${endpoint}`);
    url.search = new URLSearchParams({ q: city, appid: apiKey, units: 'metric', lang: 'ua' });

    let res;
    try {
      res = await fetchFn(url);
    } catch {
      throw new AppError(502, 'Не вдалося звʼязатися з OpenWeatherMap.');
    }

    if (res.status === 401) {
      throw new AppError(502, 'API-ключ недійсний або ще не активований (до 2 годин після створення).');
    }
    if (res.status === 404) throw new AppError(404, `Місто «${city}» не знайдено.`);
    if (res.status === 429) throw new AppError(429, 'Перевищено ліміт запитів, спробуй пізніше.');
    if (!res.ok) throw new AppError(502, 'Помилка сервісу погоди.');

    return res.json();
  }

  return {
    getCurrent: (city) => request('weather', city), // поточна погода
    getForecast: (city) => request('forecast', city), // 5 днів × кожні 3 години
  };
}
Відповідь OpenWeatherMapЩо кидає ClientЩо побачить користувач
401AppError(502)ключ недійсний або ще не активований
404AppError(404)місто не знайдено
429AppError(429)перевищено ліміт, спробуй пізніше
інші не-2xxAppError(502)помилка сервісу погоди
мережа недоступнаAppError(502)не вдалося звʼязатися

Для нашого клієнта 401 від провайдера означає «наш сервер налаштований неправильно», а не «користувач не авторизований». Тому віддаємо 502 (поганий шлюз), а не 401.

Чому fetchFn = fetch

Параметр за замовчуванням дає змогу в тесті клієнта підставити фейкову функцію й перевірити, як клієнт реагує на 401, 404, 429. Такого тесту в проєкті поки немає. Це одна з вправ.

8. Прогноз на 3 дні: розбір на прикладі

Безкоштовний тариф не має «прогнозу по днях». Є /forecast: до 40 записів із кроком 3 години. Функція buildDailyForecast перетворює їх на 3 дні.

Алгоритм

  1. Для кожного запису рахуємо місцеву дату: (dt + city.timezone) секунд від UTC.
  2. Записи сьогоднішнього дня відкидаємо, щоб «прогноз» не дублював блок «зараз».
  3. Групуємо за датою (Map зберігає порядок вставки).
  4. Беремо перші 3 групи.
  5. Для кожної: мінімум і максимум температур, середня вологість, іконка і опис із запису, найближчого до 12:00.

Числовий приклад (з тесту)

Зараз 2026-11-02 10:00 UTC, часовий пояс міста UTC+0.

Запис (UTC)t, °CЩо відбувається
02.11 15:009сьогодні → відкидається
03.11 03:002день 1: min 2, max 8, іконка із запису 12:00
03.11 12:008
04.11 12:005день 2
05.11 12:006день 3
06.11 12:007четвертий день → відкидається (slice(0, 3))
Чому важливий часовий пояс міста

Запис о 22:30 UTC для міста в UTC+2 це вже 00:30 наступного дня. Якщо рахувати дату за UTC або за часом сервера, цей запис потрапить не в той день, і min/max будуть хибні. Тому дата береться як new Date((dt + timezone) * 1000).toISOString().slice(0, 10). Використовується getUTCHours, бо до числа вже додано зсув міста.

Є окремий тест на цей випадок.

Чому нічну іконку (10n) замінено на денну (10d)

Картка дня описує день загалом. Іконка місяця на картці «завтра» збиває з пантелику, тому в коді icon.replace('n', 'd').

9. Фронтенд

public/app.jsмалює DTO
// Фронтенд лише малює готовий DTO з /api/weather. Уся логіка (мапінг, прогноз на 3 дні) — на сервері.
const $ = (id) => document.getElementById(id);

const form = $('search');
const input = $('city');
const statusEl = $('status');

const iconUrl = (code) => `https://openweathermap.org/img/wn/${code}@2x.png`;
const round = (n) => Math.round(n);

function setStatus(text, isError = false) {
  statusEl.textContent = text;
  statusEl.classList.toggle('error', isError);
}

function renderCurrent(w) {
  $('cur-city').textContent = `${w.city}, ${w.country}`;
  $('cur-desc').textContent = w.description;
  $('cur-temp').textContent = `${round(w.temp)}°C`;
  $('cur-feels').textContent = `${round(w.feelsLike)}°C`;
  $('cur-humidity').textContent = `${w.humidity}%`;
  $('cur-wind').textContent = `${w.windSpeed.toFixed(1)} м/с`;
  $('cur-pressure').textContent = `${w.pressure} гПа`;

  const icon = $('cur-icon');
  icon.src = iconUrl(w.icon);
  icon.alt = w.description;
  $('current').hidden = false;
}

function renderForecast(days) {
  const box = $('days');
  box.replaceChildren(); // createElement + textContent замість innerHTML — без XSS

  for (const d of days) {
    const el = document.createElement('div');
    el.className = 'day';

    const name = document.createElement('div');
    name.className = 'name';
    name.textContent = new Date(`${d.date}T12:00:00Z`).toLocaleDateString('uk-UA', {
      weekday: 'long', day: 'numeric', month: 'short', timeZone: 'UTC',
    });

    const img = document.createElement('img');
    img.src = iconUrl(d.icon);
    img.alt = d.description;
    img.width = img.height = 70;

    const range = document.createElement('div');
    range.className = 'range';
    range.append(`${round(d.max)}° `);
    const min = document.createElement('span');
    min.textContent = `${round(d.min)}°`;
    range.append(min);

    const hum = document.createElement('div');
    hum.className = 'hum';
    hum.textContent = `Вологість ${d.humidity}%`;

    el.append(name, img, range, hum);
    box.append(el);
  }
  $('forecast').hidden = days.length === 0;
}

async function loadWeather(city) {
  const button = form.querySelector('button');
  button.disabled = true;
  setStatus('Завантаження…');

  try {
    const res = await fetch(`/api/weather?city=${encodeURIComponent(city)}`);
    const data = await res.json();
    if (!res.ok) throw new Error(data.error || 'Щось пішло не так.');

    renderCurrent(data);
    renderForecast(data.forecast);
    setStatus('');
    localStorage.setItem('lastCity', city);
  } catch (err) {
    $('current').hidden = true;
    $('forecast').hidden = true;
    setStatus(err.message, true);
  } finally {
    button.disabled = false;
  }
}

form.addEventListener('submit', (e) => {
  e.preventDefault();
  const city = input.value.trim();
  if (city) loadWeather(city);
});

const last = localStorage.getItem('lastCity');
if (last) {
  input.value = last;
  loadWeather(last);
}
  • Логіки погоди немає. Дані вже підготовлені сервером, фронтенд їх лише показує.
  • Без innerHTML. Усе, що прийшло з API (назва міста, опис), вставляється через textContent. Якщо в даних опиниться <script>, браузер покаже його як текст (захист від XSS).
  • finally повертає кнопку в активний стан за будь-якого результату.
  • localStorage пам'ятає останнє місто: після перезавантаження сторінка одразу показує його погоду.
  • Ім'я дня тижня формує toLocaleDateString('uk-UA', ...) з timeZone: 'UTC', бо date від сервера вже локальна дата міста і її не треба зсувати вдруге.

test('buildDailyForecast: враховує часовий пояс міста', () => {
  // 22:00 UTC = 00:00 наступного дня в UTC+2 → це вже «завтра» для міста
  const tzForecast = { city: { timezone: 7200 }, list: [item('2026-11-02T22:30:00Z', 4)] };
  const [day] = buildDailyForecast(tzForecast, NOW);
  assert.equal(day.date, '2026-11-03');
});

test('getWeather: мапить відповідь у наш DTO', async () => {
  const client = {
    getCurrent: async () => ({
      name: 'Kyiv', sys: { country: 'UA' },
      weather: [{ description: 'ясно', icon: '01d' }],
      main: { temp: 10.4, feels_like: 9, humidity: 60, pressure: 1012 },
      wind: { speed: 3 },
    }),
    getForecast: async () => forecast,
  };
  const service = createWeatherService({ client, now: () => NOW });
  const w = await service.getWeather('  Kyiv ');
  assert.equal(w.city, 'Kyiv');
  assert.equal(w.humidity, 60);
  assert.equal(w.forecast.length, 3);
});

test('getWeather: порожнє місто → AppError 400, клієнт не викликається', async () => {
  const client = { getCurrent: () => assert.fail(), getForecast: () => assert.fail() };
  const service = createWeatherService({ client });
  await assert.rejects(() => service.getWeather('   '), (e) => e instanceof AppError && e.status === 400);
});

Тести використовують вбудований node:test і node:assert: ні Jest, ні Vitest не потрібні.

  • Фейковий Client — звичайний об'єкт із двома async-функціями. Це і є користь від шарів та DI.
  • Фіксований час. NOW передається як now: () => NOW, тому тест не залежить від дня запуску.
  • Тест «клієнт не викликається». Функції фейка містять assert.fail(): якщо сервіс спробує піти в мережу з порожнім містом, тест упаде.
Чого немає

Немає тестів для Client і Controller. Client тестується підміною fetchFn, Controller перевіряється запитом до запущеного сервера (як у ручній перевірці).

12. Вправи

  1. Тест для Client. Передай фейковий fetchFn, що повертає { status: 401 }, і перевір, що кинуто AppError зі статусом 502.
  2. Кеш на 10 хвилин. У Service зберігай відповідь у Map за ключем city.toLowerCase() разом із часом запису. Подивись, скільки файлів довелося змінити (має вийти один).
  3. Градуси Фаренгейта. Додай параметр ?units=imperial. Де його чекати: Controller (прочитати), Service (передати), Client (використати)?
  4. Геокодинг. Додай у Client метод для /geo/1.0/direct і поверни координати разом із погодою. Скільки шарів зачепила зміна?
  5. Зламай навмисно. Зміни slice(0, DAYS) на slice(0, DAYS + 1) і подивись, який тест впаде.
Перевір себе: чому Service не імпортує Client напряму?

Тоді не вийде підставити фейк: тест ходив би в справжню мережу з справжнім ключем. Передача через аргумент (DI) робить залежність замінною, а Service незалежним від URL і формату конкретного провайдера.

Перевір себе: що буде, якщо в Controller забути try/catch?

weatherService.getWeather асинхронна. Помилка перетворюється на відхилений Promise, який у http.createServer ніхто не обробить. Клієнт не отримає відповіді, а в Node 15+ необроблене відхилення може завершити процес.
