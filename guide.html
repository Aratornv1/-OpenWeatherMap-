Weather Dashboard: розбір коду

Вибір країни Європи і міста, поточна погода, прогноз на 3 дні та карта з шарами погоди й анімованим вітром. Сервер на Node.js без npm-залежностей ділиться на три шари: Controller, Service, Client. Нижче видно, що робить кожен файл і чому код розкладено саме так.

Node.js ≥ 20.12 0 npm-залежностей OpenWeatherMap 2.5 Open-Meteo Leaflet 1.9 node:test

1. Загальна картина

Браузер ніколи не звертається до OpenWeatherMap напряму. Він питає наш сервер, а сервер додає API-ключ і сам ходить до зовнішнього API. Так ключ лишається на сервері.

Залежності йдуть тільки вправо. Controller викликає Service, Service викликає Client. Жоден шар не знає про те, що лівіше від нього.

ШарВідповідає заНе знає про
Controllerпрочитати ?city=, віддати JSON і статусбізнес-правила
Serviceвалідація, мапінг у свою структуру, прогноз на 3 дніHTTP, URL, ключ
Clientзапити до зовнішнього API, коди 401/404/429що робити з даними

Тепер у проєкті два зовнішні джерела: OpenWeatherMap (погода, прогноз, картинки-тайли) і Open-Meteo (сітка вітру для анімації). Кожне має свого Client, а Service нічого не знає про їхні URL. Напряму браузер звертається лише до CDN (скрипти Leaflet) і до OpenStreetMap (підкладка карти): ключів там немає.

3. Шлях одного запиту

Користувач вводить Kyiv і натискає «Шукати».

  1. app.js робить fetch('/api/weather?city=Kyiv&country=UA'). Параметри збирає URLSearchParams, тож пробіли й кирилиця не ламають URL.
  2. server.js бачить шлях /api/weather і передає запит у getWeather (Controller). Інші шляхи йдуть у serveStatic.
  3. Controller бере city і country з url.searchParams і викликає weatherService.getWeather(city, country).
  4. Service обрізає пробіли, перевіряє довжину (1–100 символів) і те, що код країни (якщо є) входить у наш список із 45 країн Європи, потім через Promise.all запускає два запити одночасно: поточна погода і прогноз.
  5. Client формує URL (q=Kyiv,UA, appid, units=metric, lang=ua), робить fetch, а за статусом відповіді кидає AppError або повертає JSON.
  6. Service перетворює два сирі JSON в одну свою структуру (DTO) і викликає buildDailyForecast.
  7. Controller віддає DTO зі статусом 200. Якщо хтось кинув AppError, він віддає { error } з тим статусом, який у помилки.
  8. app.js малює картку «зараз», три картки прогнозу і карту з маркером міста (координати приходять у полі coord).

Dependency Injection вручну

Фабрика createWeatherService({ client }) бере клієнта аргументом. Сервіс не пише import { client } ... і не залежить від конкретної реалізації. У тесті сюди передають фейк, у продакшені справжній Client. Для цього не потрібен жоден фреймворк.

Також тут перевіряється конфіг: якщо ключа немає, програма завершується з зрозумілим повідомленням, а не падає пізніше з 401.

5. Controller: HTTP-шар

src/controllers/weatherController.jsшар 1
// ШАР 1 — Controller (HTTP-шар). Читає запит, викликає сервіс, формує відповідь.
// Жодної бізнес-логіки: лише «HTTP in → service → HTTP out».
import { AppError } from '../errors.js';

function sendJson(res, status, body) {
  res.writeHead(status, { 'Content-Type': 'application/json; charset=utf-8' });
  res.end(JSON.stringify(body));
}

function sendError(res, err) {
  if (err instanceof AppError) return sendJson(res, err.status, { error: err.message });
  console.error(err); // непередбачена помилка — деталі лише в лог, клієнту загальне повідомлення
  sendJson(res, 500, { error: 'Внутрішня помилка сервера.' });
}

export function createWeatherController({ weatherService }) {
  return async function getWeather(req, res, url) {
    try {
      const { searchParams } = url;
      const data = await weatherService.getWeather(searchParams.get('city'), searchParams.get('country'));
      sendJson(res, 200, data);
    } catch (err) {
      sendError(res, err);
    }
  };
}

// GET /api/wind?hour=N → { hour, hours, time, data: [U, V] } для анімації вітру
export function createWindController({ windService }) {
  return async function getWind(req, res, url) {
    try {
      sendJson(res, 200, await windService.getWindFrame(url.searchParams.get('hour')));
    } catch (err) {
      sendError(res, err);
    }
  };
}

// GET /api/countries → [{ code: 'UA', name: 'Україна' }, …] для випадаючого списку
export function createCountriesController({ weatherService }) {
  return function getCountries(req, res) {
    sendJson(res, 200, weatherService.getCountries());
  };
}

// GET /api/tiles/<layer>/<z>/<x>/<y>.png → PNG-тайл шару погоди (проксі до OpenWeatherMap).
const TILE_ROUTE = /^\/api\/tiles\/([a-z_]+)\/(\d+)\/(\d+)\/(\d+)\.png$/;

export function createTileController({ weatherService }) {
  return async function getTile(req, res, match) {
    try {
      const [, layer, z, x, y] = match;
      const png = await weatherService.getMapTile({ layer, z, x, y });
      // Дані на карті оновлюються рідко — браузер може кешувати тайл 10 хвилин
      res.writeHead(200, { 'Content-Type': 'image/png', 'Cache-Control': 'public, max-age=600' });
      res.end(png);
    } catch (err) {
      sendError(res, err);
    }
  };
}

export const matchTileRoute = (pathname) => pathname.match(TILE_ROUTE);
  • Контролер не містить логіки: бере параметр, викликає сервіс, віддає результат.
  • err instanceof AppError означає «очікувана помилка»: статус і текст уже вирішені нижче, контролер їх лише віддає.
  • Будь-яка інша помилка (баг) іде в консоль, а клієнт отримує загальне 500. Деталі помилки назовні не виходять.
  • Тут ще три обробники: createTileController (віддає PNG з Cache-Control: max-age=600), createCountriesController і createWindController. Спільна функція sendError перетворює AppError на відповідь для всіх.
Підводний камінь

Кожна функція, що кидає, має бути всередині try. Інакше відхилений Promise у http.createServer залишить запит без відповіді.

6. Service: логіка і власний формат даних

src/services/weatherService.jsшар 2
// ШАР 2 — Service (бізнес-логіка). Нічого не знає ні про HTTP, ні про URL OpenWeatherMap.
// Залежності (client, now) приходять ззовні → у тестах підставляємо фейки (Dependency Injection).
import { AppError } from '../errors.js';
import { EUROPE_COUNTRIES, EUROPE_LIST } from '../data/europeCountries.js';

const DAYS = 3;

// dt — UNIX-секунди (UTC), timezone — зсув міста від UTC у секундах → "YYYY-MM-DD" за місцевим часом.
const localDate = (dt, tz) => new Date((dt + tz) * 1000).toISOString().slice(0, 10);
const localHour = (dt, tz) => new Date((dt + tz) * 1000).getUTCHours();

// Чиста функція (без побічних ефектів) — легко тестувати.
// Прогноз = 40 записів по 3 год. Групуємо по днях міста й беремо 3 дні після сьогоднішнього.
export function buildDailyForecast(forecast, nowMs) {
  const tz = forecast.city.timezone;
  const today = localDate(Math.floor(nowMs / 1000), tz);

  const byDay = new Map();
  for (const item of forecast.list) {
    const day = localDate(item.dt, tz);
    if (day === today) continue;
    if (!byDay.has(day)) byDay.set(day, []);
    byDay.get(day).push(item);
  }

  return [...byDay.entries()].slice(0, DAYS).map(([date, items]) => {
    const temps = items.map((i) => i.main.temp);
    const humidity = items.reduce((sum, i) => sum + i.main.humidity, 0) / items.length;
    // Іконка/опис — із запису, найближчого до полудня
    const noon = items.reduce((best, i) =>
      Math.abs(localHour(i.dt, tz) - 12) < Math.abs(localHour(best.dt, tz) - 12) ? i : best,
    );
    return {
      date,
      min: Math.min(...temps),
      max: Math.max(...temps),
      humidity: Math.round(humidity),
      icon: noon.weather[0].icon.replace('n', 'd'),
      description: noon.weather[0].description,
    };
  });
}

// Дозволені шари карти (білий список): іншого рядка до OpenWeatherMap не пропустимо.
export const MAP_LAYERS = ['clouds_new', 'precipitation_new', 'wind_new', 'temp_new', 'pressure_new'];
const MAX_ZOOM = 10;

// Валідація координат тайла: у zoom z існує 2^z × 2^z тайлів (x, y від 0 до 2^z − 1).
export function parseTile({ layer, z, x, y }) {
  const [nz, nx, ny] = [z, x, y].map(Number);
  const side = 2 ** nz;
  const ok =
    MAP_LAYERS.includes(layer) &&
    Number.isInteger(nz) && nz >= 0 && nz <= MAX_ZOOM &&
    Number.isInteger(nx) && nx >= 0 && nx < side &&
    Number.isInteger(ny) && ny >= 0 && ny < side;
  if (!ok) throw new AppError(400, 'Некоректний тайл карти.');
  return { layer, z: nz, x: nx, y: ny };
}

export function createWeatherService({ client, now = Date.now }) {
  return {
    async getMapTile(params) {
      const { layer, z, x, y } = parseTile(params);
      return client.getMapTile(layer, z, x, y);
    },

    getCountries: () => EUROPE_LIST,

    async getWeather(rawCity, rawCountry) {
      const city = String(rawCity ?? '').trim();
      if (!city || city.length > 100) throw new AppError(400, 'Вкажи назву міста (до 100 символів).');

      // Країна необовʼязкова; якщо є — лише з нашого списку (білий список, як і шари карти)
      const country = String(rawCountry ?? '').trim().toUpperCase();
      if (country && !(country in EUROPE_COUNTRIES)) throw new AppError(400, 'Невідома країна.');

      const [current, forecast] = await Promise.all([
        client.getCurrent(city, country),
        client.getForecast(city, country),
      ]);

      // Мапимо чужий формат у НАШ (DTO). Фронтенд залежить лише від цієї форми.
      return {
        city: current.name,
        country: current.sys.country,
        description: current.weather[0].description,
        icon: current.weather[0].icon,
        temp: current.main.temp,
        feelsLike: current.main.feels_like,
        humidity: current.main.humidity,
        pressure: current.main.pressure,
        windSpeed: current.wind.speed,
        coord: { lat: current.coord.lat, lon: current.coord.lon }, // центр карти
        forecast: buildDailyForecast(forecast, now()),
      };
    },
  };
}

Що тут важливо

  • Валідація стоїть до будь-якого запиту: порожнє місто чи невідома країна не витрачають ліміт API. Країна й шар карти перевіряються за білим списком (EUROPE_COUNTRIES, MAP_LAYERS), а координати тайла — за межами 0…2^z−1 (parseTile). У запит до OpenWeatherMap не потрапить довільний рядок.
  • DTO. Фронтенд читає temp, feelsLike, windSpeed, а не main.temp чи wind.speed. Якщо OpenWeatherMap змінить формат, правка буде тільки тут.
  • now = Date.now як параметр. «Сьогодні» залежить від годинника. Параметр дає змогу зафіксувати час у тесті.
  • buildDailyForecast експортується окремо. Це чиста функція: ті самі вхідні дані дають той самий результат, без мережі й побічних ефектів. Її найпростіше тестувати.

7. Client: адаптер до OpenWeatherMap

src/clients/openWeatherClient.jsшар 3
// ШАР 3 — Client (патерн Adapter / Gateway).
// Єдине місце, яке знає, ЯК говорити з OpenWeatherMap: URL, параметри, коди відповідей.
// Повертає «сирий» JSON як є; помилки HTTP перетворює на AppError.
import { AppError } from '../errors.js';

const BASE_URL = 'https://api.openweathermap.org/data/2.5';
const TILE_URL = 'https://tile.openweathermap.org/map'; // Weather Maps 1.0

export function createOpenWeatherClient({ apiKey, fetchFn = fetch }) {
  async function get(url, notFoundMessage) {
    let res;
    try {
      res = await fetchFn(url);
    } catch {
      throw new AppError(502, 'Не вдалося звʼязатися з OpenWeatherMap.');
    }

    if (res.status === 401) {
      throw new AppError(502, 'API-ключ недійсний або ще не активований (до 2 годин після створення).');
    }
    if (res.status === 404) throw new AppError(404, notFoundMessage);
    if (res.status === 429) throw new AppError(429, 'Перевищено ліміт запитів, спробуй пізніше.');
    if (!res.ok) throw new AppError(502, 'Помилка сервісу погоди.');
    return res;
  }

  // country (необовʼязково) — код ISO, звужує пошук: q=Kyiv,UA
  async function request(endpoint, city, country) {
    const url = new URL(`${BASE_URL}/${endpoint}`);
    const q = country ? `${city},${country}` : city;
    url.search = new URLSearchParams({ q, appid: apiKey, units: 'metric', lang: 'ua' });
    const res = await get(url, `Місто «${city}» не знайдено${country ? ` (${country})` : ''}.`);
    return res.json();
  }

  return {
    getCurrent: (city, country) => request('weather', city, country), // поточна погода
    getForecast: (city, country) => request('forecast', city, country), // 5 днів × кожні 3 години

    // Тайл 256×256 PNG з шаром погоди. Ключ додаємо тут, на сервері, — браузер його не бачить.
    async getMapTile(layer, z, x, y) {
      const url = new URL(`${TILE_URL}/${layer}/${z}/${x}/${y}.png`);
      url.search = new URLSearchParams({ appid: apiKey });
      const res = await get(url, 'Тайл не знайдено.');
      return Buffer.from(await res.arrayBuffer());
    },
  };
}

404AppError(404)місто не знайдено

Для нашого клієнта 401 від провайдера означає «наш сервер налаштований неправильно», а не «користувач не авторизований». Тому віддаємо 502 (поганий шлюз), а не 401.

Той самий Client має й getMapTile(layer, z, x, y): він завантажує PNG-тайл і додає appid на сервері. Спільна внутрішня функція get() обробляє 401/404/429 для всіх запитів, тож коди помилок не дублюються. Для вітру є окремий клієнт openMeteoClient.js: у Open-Meteo ключа немає, зате є ліміти (див. розділ 10).

Чому fetchFn = fetch

Параметр за замовчуванням дає змогу в тесті клієнта підставити фейкову функцію й перевірити, як клієнт реагує на 401, 404, 429. Такого тесту в проєкті поки немає. Це одна з вправ.

8. Прогноз на 3 дні: розбір на прикладі

Безкоштовний тариф не має «прогнозу по днях». Є /forecast: до 40 записів із кроком 3 години. Функція buildDailyForecast перетворює їх на 3 дні.

Алгоритм

  1. Для кожного запису рахуємо місцеву дату: (dt + city.timezone) секунд від UTC.
  2. Записи сьогоднішнього дня відкидаємо, щоб «прогноз» не дублював блок «зараз».
  3. Групуємо за датою (Map зберігає порядок вставки).

Чому тайли йдуть через наш сервер

Оригінальна адреса тайла містить ?appid=КЛЮЧ. Якби браузер ходив туди напряму, ключ був би видно у DevTools. Тому /api/tiles/… — це проксі: сервер сам додає ключ, завантажує PNG і віддає його з Cache-Control: max-age=600 (дані на карті змінюються повільно).

Проксі без перевірок — діра

Якщо підставляти шар і координати в URL як є, через сервер можна піти на довільний шлях OpenWeatherMap. Тому parseTile пропускає лише п'ять відомих шарів, цілі числа та x, y у межах 0…2^z−1 (масштаб до 10). Усе інше — 400 ще до запиту назовні.

Чому не CARTO Dark Matter

Спершу була підкладка CARTO, але вона тепер вимагає ключ: без нього тайл приходить зі статусом 200, проте з написом «API KEY REQUIRED» просто на картинці. Тому взято OpenStreetMap, якому ключ не потрібен. Його політика дозволяє лише помірне використання, для великого трафіку знадобиться платний провайдер або свій сервер тайлів.

10. Анімований вітер

Тайли OpenWeatherMap — це готові картинки лише на поточний момент. Для анімації потрібні самі числа: вектор вітру в точках сітки й прогноз на кілька днів. Їх дає Open-Meteo (безкоштовний, без ключа, лише для некомерційного використання), а частинки малює плагін leaflet-velocity.

  1. Сітка. Над Європою (від 72.5°N до 32.5°N, від 25°W до 45°E) з кроком 2.5° виходить 29×17 = 493 точки. Порядок точок важливий: рядок за рядком, з півночі на південь, у рядку з заходу на схід. Так вимагає формат плагіна.
  2. Client ділить сітку на порції по 100 точок, пауза між запитами 1 секунда (ліміт 600 викликів на хвилину). Для кожної точки Open-Meteo повертає 72 години: швидкість у м/с і напрямок.
  3. Service кешує все в памʼяті на 3 години і віддає кадр на запит /api/wind?hour=N, де N=0 — поточна година.
  4. З швидкості й напрямку Service рахує дві компоненти (U — на схід, V — на північ) і збирає два масиви-«GRIB» із заголовком (lo1, la1, dx, dy, nx, ny).
  5. Браузер передає їх у L.velocityLayer, а плагін малює частинки на canvas поверх карти. Повзунок часу просить новий кадр, і setData оновлює шар без перебудови.

Напрямок вітру: пастка

Метеорологи вказують напрямок, звідки дме вітер, а не куди. Тому знаки мінус у формулі: u = −швидкість·sin(напрямок), v = −швидкість·cos(напрямок).

// ШАР 3 — Client для Open-Meteo (безкоштовний, без ключа, лише некомерційне використання).
// Ліміти безкоштовного API: 600 викликів/хв, 10 000/добу; кожна точка в запиті рахується як виклик —
// тому сервіс над нами кешує сітку та ділить її на порції.
import { AppError } from '../errors.js';

const URL_FORECAST = 'https://api.open-meteo.com/v1/forecast';

export function createOpenMeteoClient({ fetchFn = fetch } = {}) {
  return {
    // points: [{ lat, lon }, …]. Повертає масив (по одному елементу на точку, в тому ж порядку):
    //   { hourly: { time: [unix-секунди], wind_speed_10m: [м/с], wind_direction_10m: [° звідки дме] } }
    async getWind(points, hours) {
      const url = new URL(URL_FORECAST);
      url.search = new URLSearchParams({
        latitude: points.map((p) => p.lat).join(','),
        longitude: points.map((p) => p.lon).join(','),
        hourly: 'wind_speed_10m,wind_direction_10m',
        wind_speed_unit: 'ms',
        forecast_hours: String(hours),
        timeformat: 'unixtime',
        cell_selection: 'nearest', // без «підлаштування під сушу» — над морем лишаємось над морем
      });

      let res;
      try {
        res = await fetchFn(url);
      } catch {
        throw new AppError(502, 'Не вдалося звʼязатися з Open-Meteo.');
      }
      if (res.status === 429) throw new AppError(429, 'Open-Meteo: перевищено ліміт запитів, спробуй пізніше.');
      if (!res.ok) throw new AppError(502, 'Помилка сервісу вітру (Open-Meteo).');

      const body = await res.json();
      return Array.isArray(body) ? body : [body]; // для однієї точки API повертає обʼєкт, а не масив
    },
  };
}

// ШАР 2 — Service для анімованої карти вітру.
// Бере прогноз вітру по сітці над Європою, кешує його (щоб не вичерпати ліміти Open-Meteo)
// і віддає по одній годині у форматі, який розуміє leaflet-velocity: [U-компонента, V-компонента].
import { AppError } from '../errors.js';

// Сітка: рядки йдуть з ПІВНОЧІ на південь, колонки — із заходу на схід (так вимагає leaflet-velocity).
export const GRID = { la1: 72.5, la2: 32.5, lo1: -25, lo2: 45, step: 2.5 };

const FORECAST_HOURS = 72;
const CHUNK_SIZE = 100; // точок в одному запиті до Open-Meteo
const TTL_MS = 3 * 60 * 60 * 1000; // модель оновлюється раз на кілька годин — частіше питати марно
const RETRY_AFTER_FAIL_MS = 10 * 60 * 1000;

const round2 = (n) => Math.round(n * 100) / 100;

export function gridSize(grid = GRID) {
  return {
    ny: Math.round((grid.la1 - grid.la2) / grid.step) + 1,
    nx: Math.round((grid.lo2 - grid.lo1) / grid.step) + 1,
  };
}

// Усі точки сітки в порядку даних: рядок за рядком, з північного заходу.
export function gridPoints(grid = GRID) {
  const { ny, nx } = gridSize(grid);
  const points = [];
  for (let r = 0; r < ny; r++) {
    for (let c = 0; c < nx; c++) {
      points.push({ lat: grid.la1 - r * grid.step, lon: grid.lo1 + c * grid.step });
    }
  }
  return points;
}

// Метеорологічний напрямок — ЗВІДКИ дме вітер (0° = північний, дме на південь).
// U — на схід, V — на північ.
export function toUV(speed, directionDeg) {
  const rad = (directionDeg * Math.PI) / 180;
  return { u: -speed * Math.sin(rad), v: -speed * Math.cos(rad) };
}

// Збирає два «GRIB-подібні» обʼєкти (U і V) для leaflet-velocity з масивів значень сітки.
export function buildVelocityData(uValues, vValues, refTimeIso, grid = GRID) {
  const { nx, ny } = gridSize(grid);
  const header = (parameterNumber, parameterNumberName) => ({
    parameterCategory: 2, parameterNumber, parameterNumberName, parameterUnit: 'm.s-1',
    lo1: grid.lo1, lo2: grid.lo2, la1: grid.la1, la2: grid.la2,
    dx: grid.step, dy: grid.step, nx, ny, refTime: refTimeIso,
  });
  return [
    { header: header(2, 'U-component_of_wind'), data: uValues },
    { header: header(3, 'V-component_of_wind'), data: vValues },
  ];
}

const sleepMs = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

export function createWindService({ client, now = Date.now, sleep = sleepMs, pauseMs = 1000 }) {
  let cache = null; // { fetchedAt, startSec, hours, speed: [[…]], dir: [[…]] } — по точках
  let inflight = null;

  async function fetchGrid() {
    const points = gridPoints();
    const speed = [];
    const dir = [];
    let times = null;

    for (let i = 0; i < points.length; i += CHUNK_SIZE) {
      if (i > 0) await sleep(pauseMs); // не частимо: ліміт 600 викликів на хвилину
      const chunk = points.slice(i, i + CHUNK_SIZE);
      const results = await client.getWind(chunk, FORECAST_HOURS);
      if (results.length !== chunk.length) throw new AppError(502, 'Open-Meteo повернув неповні дані.');

      for (const r of results) {
        times ??= r.hourly.time;
        speed.push(r.hourly.wind_speed_10m);
        dir.push(r.hourly.wind_direction_10m);
      }
    }
    return { fetchedAt: now(), startSec: times[0], hours: times.length, speed, dir };
  }

  // Свіжий кеш → віддаємо. Інакше оновлюємо; кілька одночасних запитів ділять один запит назовні.
  async function ensureFresh() {
    if (cache && now() - cache.fetchedAt < TTL_MS) return cache;
    inflight ??= fetchGrid()
      .then((fresh) => (cache = fresh))
      .catch((err) => {
        if (!cache) throw err;
        cache = { ...cache, fetchedAt: now() - TTL_MS + RETRY_AFTER_FAIL_MS }; // лишаємо старе, спробуємо пізніше
        return cache;
      })
      .finally(() => { inflight = null; });
    return inflight;
  }

  return {
    // hour = 0 — поточна година, 1 — наступна і т.д.
    async getWindFrame(rawHour) {
      const hour = Number(rawHour ?? 0);
      if (!Number.isInteger(hour) || hour < 0) throw new AppError(400, 'Некоректна година прогнозу.');

      const c = await ensureFresh();
      // Кеш міг зʼявитись кілька годин тому: зсуваємо початок до поточної години
      const base = Math.max(0, Math.floor((now() / 1000 - c.startSec) / 3600));
      const idx = base + hour;
      const available = c.hours - base;
      if (idx >= c.hours) throw new AppError(400, `Прогноз доступний лише на ${available} год.`);

      const u = [];
      const v = [];
      for (let p = 0; p < c.speed.length; p++) {
        const wind = toUV(c.speed[p][idx] ?? 0, c.dir[p][idx] ?? 0);
        u.push(round2(wind.u));
        v.push(round2(wind.v));
      }
      const timeIso = new Date((c.startSec + idx * 3600) * 1000).toISOString();
      return { hour, hours: available, time: timeIso, data: buildVelocityData(u, v, timeIso) };
    },
  };
}

Кожна точка в запиті рахується як окремий виклик. Одне оновлення сітки — це ≈493 виклики. Кеш на 3 години дає до 8 оновлень на добу, тобто ≈3 900 викликів: у межах ліміту. Модель прогнозу все одно оновлюється не частіше, ніж раз на кілька годин.

Кожен перезапуск сервера скидає кеш

Кеш лежить у памʼяті, тож після npm start перший запит знову витратить ≈493 виклики. Під час розробки це можна не помітити, але 20 перезапусків за день уже дорівнюють половині добового ліміту.

Навіщо inflight: один запит назовні на багатьох відвідувачів

Коли кеш застарів, перші кілька запитів приходять майже одночасно. Без inflight кожен запустив би свої 5 порцій до Open-Meteo. З ним усі чекають на один спільний Promise. Тест «одночасні запити ділять один виклик» це перевіряє.

Що, якщо Open-Meteo не відповідає

Якщо старий кеш є, Service віддає його й відкладає наступну спробу на 10 хвилин, а не б'є по сервісу на кожен запит. Якщо кешу ще немає, користувач бачить помилку під картою, а решта сторінки працює.

Чому година рахується від поточного часу, а не від початку кешу

Кеш може бути отриманий 3 години тому. Тоді «година 0» мала б показувати вітер трьох-годинної давності. Service рахує зсув base = (зараз − початок прогнозу) / 1 год і додає його до запитаної години, а hours у відповіді — це кількість годин, що реально лишилась.

async function loadWindFrame(hour) {
  const seq = ++windSeq;
  // Перший запит за ~3 години заповнює кеш на сервері (кілька порцій до Open-Meteo) — це займає кілька секунд
  if (!weatherLayer) $('map-hint').textContent = 'Завантажую вітер… (перший раз це кілька секунд)';
  try {
    const res = await fetch(`/api/wind?hour=${hour}`);
    const body = await res.json();
    if (!res.ok) throw new Error(body.error || 'Не вдалося завантажити вітер.');
    if (seq !== windSeq || activeLayer !== WIND_ANIM || !map) return; // користувач вже перейшов далі

    hourSlider.max = String(body.hours - 1);
    $('hour-label').textContent = formatHour(body.time);

    if (weatherLayer) {
      weatherLayer.setData(body.data);
    } else {
      weatherLayer = L.velocityLayer({
        data: body.data,
        displayValues: true,
        displayOptions: {
          velocityType: 'Вітер', position: 'bottomleft', emptyString: 'Немає даних',
          angleConvention: 'meteoCW', speedUnit: 'ms', directionString: 'Звідки', speedString: 'Швидкість',
        },
        minVelocity: 0, maxVelocity: 15, velocityScale: 0.01, opacity: 0.9,
      }).addTo(map);
    }
    $('map-hint').textContent = LAYER_HINTS[WIND_ANIM];
  } catch (err) {
    if (seq !== windSeq) return;
    stopPlay();
    $('map-hint').textContent = `Вітер: ${err.message}`;
  }
}

function setLayer(name) {
  activeLayer = name;
  for (const btn of $('layers').children) btn.classList.toggle('active', btn.dataset.layer === name);

  weatherLayer = null;
  if (isWind) loadWindFrame(Number(hourSlider.value));
  else weatherLayer = makeWeatherLayer(name).addTo(map);
}

  }

  • Логіки погоди немає. Дані вже підготовлені сервером, фронтенд їх лише показує.
  • Без innerHTML. Усе, що прийшло з API (назва міста, опис), вставляється через textContent. Якщо в даних опиниться <script>, браузер покаже його як текст (захист від XSS).
  • finally повертає кнопку в активний стан за будь-якого результату.
  • localStorage пам'ятає останнє місто й країну: після перезавантаження сторінка одразу показує його погоду.
  • Карта — додаткова. renderMap виконується у власному try/catch. Якщо Leaflet не завантажився з CDN або сервер не повернув координати, блок карти ховається, а пошук і картки погоди працюють далі. Раніше помилка карти потрапляла в загальний catch і «ламала» весь пошук.
  • Номер запиту windSeq. Відповідь від сервера може прийти вже після того, як користувач рушив повзунок далі чи змінив шар. Кожен запит має номер, а застарілі відповіді ігноруються.
  • Debounce 200 мс на повзунку. Поки його тягнуть, сервер не засипається запитами: надсилається лише останнє положення. Кнопка ▶ міняє годину раз на секунду.
  • Список країн додається через new Option(name, code), а не через innerHTML.
  • Ім'я дня тижня формує toLocaleDateString('uk-UA', ...) з timeZone: 'UTC', бо date від сервера вже локальна дата міста і її не треба зсувати вдруге.

Тести використовують вбудований node:test і node:assert: ні Jest, ні Vitest не потрібні.

  • Фейковий Client — звичайний об'єкт із двома async-функціями. Це і є користь від шарів та DI.
  • Фіксований час. NOW передається як now: () => NOW, тому тест не залежить від дня запуску.
  • Тест «клієнт не викликається». Функції фейка містять assert.fail(): якщо сервіс спробує піти в мережу з порожнім містом, тест упаде.
  • Сервіс вітру без мережі й без годинника. Фейковий Open-Meteo повертає однаковий вітер, а now і sleep передаються ззовні. Тому тест кешу не чекає 3 години, а паузи між порціями миттєві.
  • Не лише «щасливий» шлях: некоректна година → 400; Open-Meteo впав, але кеш є → віддаємо старий; впав, а кешу немає → помилка.
Чого немає

Немає тестів для Client і Controller. Client тестується підміною fetchFn, Controller перевіряється запитом до запущеного сервера (як у ручній перевірці).

15. Вправи

  1. Тест для Client. Передай фейковий fetchFn, що повертає { status: 401 }, і перевір, що кинуто AppError зі статусом 502.
  2. Кеш на 10 хвилин. У Service зберігай відповідь у Map за ключем city.toLowerCase() разом із часом запису. Подивись, скільки файлів довелося змінити (має вийти один).
  3. Градуси Фаренгейта. Додай параметр ?units=imperial. Де його чекати: Controller (прочитати), Service (передати), Client (використати)?
  4. Геокодинг. Додай у Client метод для /geo/1.0/direct і поверни координати разом із погодою. Скільки шарів зачепила зміна?
  5. Зламай навмисно. Зміни slice(0, DAYS) на slice(0, DAYS + 1) і подивись, який тест впаде.
  6. Тест для openMeteoClient. Фейковий fetchFn має повертати об'єкт замість масиву (так API відповідає для однієї точки), а потім статус 429. Що має кинути Client?
  7. Сітка 1°. Скільки точок вийде для Європи з кроком 1° і скільки викликів на добу це дасть при кеші на 3 години? Чи вкладемось у 10 000? Що можна змінити (TTL, межі, крок)?
  8. Кеш на диск. Збережи сітку вітру у файл, щоб перезапуск сервера не витрачав 493 виклики. Який шар має знати про файл?
  9. Опади. Додай у Client змінну precipitation з Open-Meteo. Які файли зміняться, якщо кольорову сітку малювати на canvas самостійно?
Перевір себе: чому Service не імпортує Client напряму?

Тоді не вийде підставити фейк: тест ходив би в справжню мережу з справжнім ключем. Передача через аргумент (DI) робить залежність замінною, а Service незалежним від URL і формату конкретного провайдера.

Перевір себе: що буде, якщо в Controller забути try/catch?

weatherService.getWeather асинхронна. Помилка перетворюється на відхилений Promise, який у http.createServer ніхто не обробить. Клієнт не отримає відповіді, а в Node 15+ необроблене відхилення може завершити процес.

Відомі обмеження

Open-Meteo безкоштовний лише для некомерційного використання, а кожен перезапуск сервера скидає кеш і витрачає ≈493 виклики з добових 10 000.
